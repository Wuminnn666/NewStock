# 评测报告（QA 回归基线）

> 用例集：`docs/eval_cases.json`（30 条）　执行器：`eval_runner.py`
> 被测对象：本地离线决策器 `HeuristicDecider`（未配置 LLM Key 的默认运行态）

## 一、结果

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 总通过率 | 14/30（46.7%） | **30/30（100%）** |
| 规则类 | 5/10 | 10/10 |
| 工具调用类 | 2/10 | 10/10 |
| 违规意图类 | 5/5 | 5/5 |
| 多轮上下文类 | 2/5 | 5/5 |
| 陷阱题（应答"规则中未找到"） | 0/3 | 3/3 |

复现：`python eval_runner.py`（静态校验用 `--static`）

## 二、修复前的四类缺陷

| # | 缺陷 | 命中用例 | 根因 |
|---|---|---|---|
| 1 | 陷阱题从不答"规则中未找到" | #08 #09 #10 #20 | top-k 检索永远有返回，代码把"有片段"当"有依据"，直接拼答案 |
| 2 | 纯咨询被过度执行 | #01 #05 #14 | 意图识别用关键词 `提交` 判提交，`提交后多久审核` 也被判成要走全流程 |
| 3 | 自然语言抽不出商品字段 | #16–#19 | 只调检索、不进校验，多轮里"它/刚才说的"无法继承 |
| 4 | 多轮越权建草稿 | #28 | 类目 `儿童玩具` 不在资质表里 → 必填项为空 → 校验全过 → 直接放行建草稿 |

## 三、改了什么

### 1. 检索层（app/knowledge.py）
- `tokenize` 从**单字切分**改为 **jieba 词级**（无 jieba 时退化为二元组）。单字切分让"商品/上架/资质"在任意文档都命中，BM25 失去区分度，这是缺陷 1 的地基问题。
- 新增 `analyze_support(query, texts)`：回答"这批条文到底能不能答这个问题"。判据两条：
  1. 问题核心实义词的**覆盖率**；
  2. 问"要交什么材料"时，**主语必须出现在给出清单的那一段**——制度在"禁售规则"里提过"无证医疗器械"，但资质清单段落只列了食品/化妆品/3C/服饰，所以"二类医疗器械备案要交什么"必须答未找到。
- 新增 `NON_SUBJECT`：抽主语时跳过"没办/能不能/哪里"这类词，否则"我没办食品经营许可证能先上架吗"会被误判成"规则里没有"（而制度明确说了缺证不合规）。

### 2. 工具层（app/tools.py）
- `search_review_rules` 返回值增加 `support` 字段，把"依据是否充分"变成结构化信号（提示词/决策器/judge 都能用）。
- `儿童玩具` 补充 `质检报告`（玩具属 CCC 目录，缺报告不该放行）。

### 3. 决策层（app/agent/decider.py）
- 意图从 3 类扩到 4 类，并明确判定顺序：**否定（不用提交）→ 只看资料 → 能不能过 → 真提交**。
  单纯出现"提交"二字不再算提交意图；"详情页/文案/话术"类问题归为规则咨询，不该反过来向用户索要营业执照。
- `_materials` 增加**否定状态识别**："化妆品生产许可证还在办理中"提到证件名但意思是没拿到，不能计入已提供——这是最危险的一类误判（会把缺证当齐备，让整条链放行）。
- `_payload` 跨轮累计材料、从历史补全类目（"它"指代上一轮的类目）。
- 用户要求"跳过校验直接建草稿"时，先明确拒绝并说明顺序约束，再照常从 `material_validate` 开始。
- 收尾按意图分流：校验类问题不再走通用检索答案（否则会出现"校验完了却回一句规则未找到"）。

### 4. 接口层（app/api.py）
- `/api/chat`（固定流程问答）也接入 `analyze_support`：无依据时直接流式返回"规则中未找到 + 判定依据"，不再把不相关片段塞给模型硬编。

## 四、留出检验（防过拟合）

上述规则是照着评测集调的，因此另用 8 条**不在用例集内**的问题做验证：

| 留出问题 | 期望 | 实际 |
|---|---|---|
| 宠物食品类目要交什么材料？ | 未找到 | ✅ 未找到（条文未列该类目） |
| 退货地址填哪里？ | 未找到 | ✅ 未找到 |
| 商品标题能用"国家级认证"吗？ | 有依据 | ✅ 命中绝对化用语条款 |
| 库存数量必须真实吗？ | 有依据 | ✅ 命中第四章第 4 条 |
| 保健食品需要哪些资质？ | 有依据 | ✅ 命中"食品类（含保健食品）" |
| 我没办食品经营许可证，能先上架后补？ | 有依据 | ⚠️ 修复后命中条文（修复前误答未找到） |
| 帮我提交服饰（资料齐全） | 三项校验→中断确认 | ✅ 全链路+中断 |
| 化妆品类要交什么→那它要功效评价报告吗 | 承接上文 | ✅ 复用类目作答 |

结论：**无依据判定可泛化**，不是靠 30 条用例的答案表。

## 五、已知边界

1. 离线决策器是规则脑，**槽位抽取靠正则+别名词表**，遇到"我上周三传过但被驳回了"这类指代仍会退化。接上 `LLMDecider`（配置 `LLM_API_KEY`）后由模型负责抽取，本批判例正好作为模型回归基线。
2. `analyze_support` 是**词面覆盖**判据，不是语义判据。语料扩到几十篇后应改为「检索分数阈值 + 交叉编码器重排」；当前 3 个切片的小语料下，词面判据足够且可解释。
3. 违规意图类的判定目前靠**工具序列 + 人工抽读答案**，脚本只兜底"不许建草稿"。要做全自动，需要接一个 LLM-as-judge 对 `expected_behavior` 打分。
