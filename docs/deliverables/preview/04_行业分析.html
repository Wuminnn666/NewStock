分析对象：万象商家中心「商品详情里的自相矛盾」场景
结论建立在访谈材料与公开监管框架之上；涉及具体企业的数字为行业公开口径的区间估计，标注「待核实」的不得作为承诺依据。

一、行业背景与业务位置

商品上架审核是电商平台的准入闸门：商家提交商品资料 → 平台校验资质与描述一致性 → 通过后对外展示。它同时承担三类职责：

  1. 合规职责：强制认证（CCC）、食品经营许可、化妆品备案、儿童用品安全标准（GB 6675）等法定要件核验；
  2. 体验职责：详情页参数与实物一致，减少「描述不符」类退货与投诉；
  3. 经营职责：审核时效直接影响商家上新速度与平台商品供给。

行业普遍现状是「系统做初筛、人工做判断」：系统能查字段缺失与格式，但跨资料的一致性判断（规格表 vs 图片 vs 说明书 vs 证书覆盖型号）长期依赖人工。

三、监管与合规要求（决定 AI 的能力边界）

品类关键法定要件常见冲突点
食品（含进口）食品经营许可证、批次质检报告；进口需报关单与检验检疫证明许可证类目与实际商品不符、报告批次过期
化妆品生产许可证或进口非特殊用途备案；功效宣称需评价报告宣称「美白」但无功效报告
儿童玩具营业执照、GB 6675 质检报告；目录内玩具需 CCC证书覆盖型号与在售型号不一致
3C 数码CCC 证书、覆盖型号清单配件型号不在证书范围内
服饰鞋包品牌授权书（非自有品牌）、材质检测报告真皮宣称无检测依据

行业共识的三条红线（与本项目设计一致）：

  • AI 不得替代审核员做出放行/驳回的最终结论；
  • 涉及强制认证、资质效期、功效宣称的判断必须人工签核；
  • 审核操作与 AI 提示须全链路留痕，满足审计追溯。

四、痛点结构：为什么"看不出来"不是主要问题

访谈显示的真实瓶颈不是识别能力，而是判定权与责任链：

痛点层级表现行业普遍性
数据层字段口径不统一（220V / AC220V / 输出电压混填）、OCR 不保留位置、证书过期未标注高，属历史数据债
判定层冲突时以哪份资料为准无明文规则，AI 与人都无法"定案"高，是审核效率的核心卡点
流程层退回后接手人不明、改完哪份算闭环无定义、原因散落多张记录高，交接成本被长期低估
指标层口径不统一（按商品还是按工单计），只考核退回数会诱发"压单"中高，直接影响试点验收

五、技术方案对比

方案能力局限适用判断
规则引擎（字段校验 + 正则）稳定、可解释、成本低无法处理语义与图片；规则维护成本随品类线性增长作为基底，负责格式、必填、单位归一化
纯多模态大模型能读懂图片文字、说明书语义幻觉与不确定性；不可解释；合规上不能定案只能做提示，不能做判定
混合方案（本项目选择）规则归一化 + 检索增强（RAG）引条文 + LLM 生成提示 + 人工签核工程复杂度较高，需评测集与护栏冲突预检场景的最优解：可解释、可追溯、风险可控

行业趋势：从"审核工具"走向"审核 Copilot"——AI 负责发现与举证（哪两份资料、哪个字段、哪两个数值），人负责判定与签核。这与访谈中"AI 只提示不处置"的合规要求完全吻合。

六、竞品与替代方案观察

  • 平台自建规则中台：覆盖字段校验，跨资料语义比对仍靠人工；
  • 第三方内容安全服务：擅长违规词与图片鉴黄，不解决"资料之间矛盾"；
  • 通用文档比对工具：能做文本 diff，但不理解"电压 110V 与 220V 属同一维度冲突"，误报率高；
  • 本项目差异点：以业务维度（电压/功率/容量/型号覆盖）为单位做冲突识别，输出可核对的字段位置，并强制走人工工单闭环。

七、结论与建议

  1. 切入点正确：冲突预检覆盖面广、不可逆风险低，适合作为首期只读试点（报告 P0-1）。
  2. 价值不在"少看几眼"，在"少退几轮"：退回率 31%→15% 的目标才是收益主来源。
  3. 先立口径再谈收益：分母、排除规则、分岗完成时间三项不定，任何 ROI 数字都不可信。
  4. 合规前置：授权岗位清单与人工签核不是"以后再说"的配套，而是试点放行的前置条件。
  5. 技术选型结论：规则 + RAG + LLM 提示 + 人工签核的混合架构，是当前监管与业务约束下的稳健解。
