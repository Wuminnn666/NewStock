四、Agent 编排设计

4.1 主循环（Harness）

用户输入
  → 安全前置（注入检测/套取提示词 → 直接拒绝 + 留痕）
  → 意图识别：qa / material_only / validate / submit
  → 计划：按意图生成工具序列（只读工具 → 校验工具 → 写工具）
  → 循环（≤5 轮）：执行工具 → 记录 agent_steps → 决策器决定下一步
  → 若下一步为 create_goods_draft：强制中断，生成确认单（SSE 事件 confirm_required）
  → 用户确认（/api/agent/confirm）：校验 precheck_token + 三项校验通过
  → 创建草稿 / 拒绝并说明原因

4.2 校验链与门禁

material_validate → qualification_audit → compliance_check → attribute_conflict_check
        │                    │                    │                    │
        └──── 任一 failed ───┴────────────────────┴──── 生成待补清单 / 转人工
                                                      ↓
                                          create_goods_draft（需 precheck_token）
  • precheck_token：由上游校验通过后签发，绑定 run_id 与内容哈希；缺失或不匹配 → E-STATE-001/002 拒绝。
  • 冲突分支：attribute_conflict_check 检出冲突时禁止建草稿，必走 escalate_manual 建工单。
  • 只读白名单：/api/agent/tools 仅暴露只读工具；写类工具一律 403，杜绝绕过确认单直接建草稿。

4.3 工具契约（节选）

工具类型输入输出约束
search_review_rules只读query, top_kresults[], support{supported,coverage,subject}依据不足必须返回 supported=false
get_category_requirements只读categoryrequired[]类目未知返回空并提示
material_validate只读session_id, payloadpassed, missing[]办理中/过期不算已提供
qualification_audit只读同上passed, issues[]证书型号覆盖校验
compliance_check只读同上passed, violations[]违禁词/功效宣称
attribute_conflict_check只读同上passed, conflicts[{dimension, fieldA, fieldB}]只提示不处置
create_goods_draft写payload, precheck_tokendraft_id必须人工确认 + token 校验
escalate_manual写biz_ref, reason, conflict_detailtask_no, handler_role三硬字段必填
request_missing_material写session_id, itemstask_id, missing[]任一校验失败时调用

五、检索与回答质量

  • 混合检索：BM25（词级 jieba）+ FAISS 向量（离线模式用稳定哈希伪向量，可切真实 embedding），得分融合后取 top-k。
  • 依据判定 analyze_support()：覆盖率 + 资质清单段落约束 + 主语抽取，避免"top-k 永远有返回"的假命中。
  • 回答生成两级提炼：① 能算缺口就直接给结论（类目要求 − 已提供 → 还缺 XX）；② 从命中条文按关键词重合度抽句，不贴整段。
  • 不编造约束：依据不足时明确输出"未找到相关条文"并给出建议，不推测标准。
  • 评测：30 条用例（规则 10 / 工具 10 / 违规 5 / 多轮 5）全通过；另有 8 条留出检验。

六、安全设计

风险措施
提示词注入detect_injection() 命中即拒绝并记 security_events；检索前 strip_injection() 剥离注入前缀
套取系统提示is_prompt_extraction()（套取动词 + 对象双条件），避免误伤正常提问
越权建草稿工具白名单 + precheck_token 门禁 + 确认单三重
资源耗尽滑动窗口限流（chat/agent/login 分档）、日 token 配额、LLM 并发信号量、SSE 连接上限（超额 429/42904）
敏感信息输出侧与后台展示脱敏（手机号/证件号）；日志截断存储
密钥管理ENV=prod 校验 SECRET_KEY；演示默认口令须在上线前替换

七、可观测性

  • GET /api/health：status / degraded / agent_enabled / sse{active,peak,rejected,limit} / llm_today / knowledge_snapshot{chunks,built_at,age_seconds,stale}。
  • GET /api/admin/metrics：每个指标带分母定义与排除规则；分工具 p50/avg 耗时；人工队列在办/已闭环；确认单通过率。
  • GET /api/admin/security-events：注入尝试、套取提示词留痕（脱敏后展示）。
  • 逐轮轨迹 /admin/agent：每轮工具、参数、结果摘要、耗时。
