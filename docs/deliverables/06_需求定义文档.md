# 需求定义文档 · 万象商家中心商品上架审核 AI 改造

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.0 |
| 编制依据 | 六人访谈记录、典型事件访谈（唐映秋）、业务需求发现报告、四份客户简报 |
| 需求性质 | **待验证假设**——调查覆盖完整不等于业务需求已确认，全部需求须经试点取数验证 |
| 适用范围 | 商品提交后、人工审核前的只读预检段；不含自动放行、自动驳回 |
| 编制日期 | 2026-11-06 |

## 一、痛点清单（访谈证据 → 问题定义）

| 编号 | 痛点 | 证据来源 | 现状量化 | 影响 |
|---|---|---|---|---|
| PA-1 | 冲突时以哪份资料为准无明文，无法定案 | 唐映秋（f20） | 退回率 31%，目标 15% | 同一单反复退回 2–3 轮 |
| PA-2 | 退回后接手人不明、闭环标准缺失 | 唐映秋、傅景 | 交接靠人盯，无工单字段 | 责任无法追溯，审计不可还原 |
| PA-3 | 同一商品多次退回，原因散落多张记录 | 唐映秋、林亦舟 | 交接时易漏，靠便签/聊天 | 重复沟通，商家体验差 |
| PA-4 | 字段口径不统一、OCR 无位置、证书过期未标注 | 秦芮 | 电压填法至少 3 种 | 冲突误报高，真冲突被淹没 |
| PA-5 | 接口只读、数据 T+1，快照过期无标识 | 秦芮 | 最长滞后 1 天 | "改了还被退" |
| PA-6 | 无固定分母与验收口径，只考核退回数会诱发压单 | 唐映秋反问、傅景 | 口径未定 | 指标失真，试点无法验收 |
| PA-7 | 审核人力被跨资料核验占满 | 顾明岚、报告 | 占审核时间约 60%，初审 18 分钟 | 单均成本高，上新慢 |

## 二、AI 改造点与优先级

优先级判定规则：**风险不可逆性 × 价值 × 可验证性**。涉及放行/驳回的一律不做（合规红线）。

| 编号 | 改造点 | 优先级 | 为什么 | 明确不做 |
|---|---|---|---|---|
| REQ-1 | **属性冲突预检**（跨资料同维度数值比对，只读提示） | **P0** | 覆盖 60% 耗时环节，不可逆风险低 | 不判定哪份为准、不自动退回 |
| REQ-2 | **数据质量门 + 人工修复队列**（主编号/单位归一/效期标注） | **P0** | 不先做，冲突无法稳定暴露 | 不自动改写商家数据 |
| REQ-3 | **转人工兜底**（工单三硬字段：触发原因/接手人/确认时间） | **P0** | 合规要求"不能只给模糊提醒" | 不自动分派处罚、不代替签核 |
| REQ-4 | **权限与授权岗位清单**（按品类签核人、查看范围、禁借账号） | **P0** | 试点放行的前置条件 | 不开放写入回写（首期） |
| REQ-5 | **快照兜底**（时间戳 + 超周期标"暂未更新"） | P1 | 接口 T+1，避免旧数据当实时 | 不承诺实时一致性 |
| REQ-6 | **指标口径**（固定分母、排除规则、分岗完成时间） | P1 | 无口径则无法验收 | 不用单一指标考核一线 |
| REQ-7 | 知识库 RAG 问答（规则条文可引用） | P1 | 降低"规则怎么理解"的沟通成本 | 不给法律意见、不编造条文 |
| REQ-8 | 多模态 OCR 位置保留（图片文字定位到框） | P2 | 提升冲突举证精度 | 不做图片真伪鉴定 |

## 三、需求规格（规格化描述）

### REQ-1 属性冲突预检

- **输入**：商品标题、详情描述、规格表、图片文字（OCR 结果）、证书型号清单。
- **处理**：按"维度"归一化（电压 V、功率 W、容量 mAh/mL、重量 g、型号字符串），同一维度跨字段比对；数值差异超阈值或型号不在覆盖范围即判为冲突。
- **输出**：冲突列表 `[{维度, 字段A位置+值, 字段B位置+值, 差异说明}]`；**不含结论性建议**。
- **约束**：只读；不得修改任何商家资料；不得给出"以哪份为准"的判断。
- **异常**：无字段 → 返回"资料不足，无法预检"；单位无法归一 → 标记"待人工确认"而非猜测。

### REQ-2 数据质量门与修复队列

- **输入**：商品主编号、事件时间、版本、单位字段、证书有效期。
- **规则**：主编号缺失/重复 → 拒绝进入预检；单位混用 → 归一化并记录原文；证书过期 → 标注"已过期"并强制转人工。
- **输出**：质量报告（通过项/修复项/拒绝项）+ 修复队列条目。
- **约束**：修复由人执行，系统只登记与提示。

### REQ-3 转人工兜底

- **触发条件**（满足任一即入队）：属性冲突、资质临期/过期、证书型号不覆盖、关键系统不可用、AI 置信度低于阈值。
- **工单必填**：触发原因、接手人（岗位）、确认时间；缺任一项视为未闭环。
- **闭环判定**：接手人完成判定并回填确认时间；重复确认须拒绝（防重复处置）。
- **约束**：AI 不得代替审核员下结论；工单不得自动关闭。

### REQ-4 权限与授权

- 按品类定义签核岗位与查看范围（参数/图片/说明书/证书/退回原因）。
- 账号不得借用；审核员不得代合规专员签核。
- 所有签核动作留痕：操作人、时间、AI 建议、人工是否覆盖。

### REQ-5 快照兜底

- 知识/数据快照带 `built_at` 时间戳；超过一个同步周期（默认 15 分钟 / T+1）标记 `stale`，界面显示"暂未更新"。
- 接口中断时进入只读快照模式并提示数据截止时间；恢复后按业务编号去重补齐。

### REQ-6 指标口径

- 每个指标必须声明：分子、分母、排除规则、统计周期、分岗拆解。
- 固定分母约定：执行失败计入分母不剔除；一次审核流程只计一张确认单。
- 双轨考核：效率（退回次数/时长）+ 质量（交接责任可追溯），并设"压单率"反向约束。

## 四、需求边界（不做什么）

| 边界项 | 说明 |
|---|---|
| 不做自动放行 / 自动驳回 | 合规红线：最终决定必须由授权岗位签核 |
| 不改写商家资料 | 首期仅只读；写操作走单独审批 |
| 不做资质真伪鉴定 | 仅校验"是否具备/是否过期/型号是否覆盖" |
| 不承诺实时数据 | 以快照 + 时间戳兜底，明确告知滞后 |
| 不替代法律/合规意见 | 规则解释以制度文档为准，AI 只引用 |
| 不覆盖售中售后 | 本次范围止于"上架前审核" |

## 六、验收标准清单

| 编号 | 验收项 | 通过标准（可量化） | 验证方法 |
|---|---|---|---|
| AC-01 | 冲突召回 | 历史样本回放，属性冲突召回率 ≥ 97% | 抽取 200 单历史冲突单回放，人工标注为金标准 |
| AC-02 | 冲突单不误放行 | 冲突单 100% 进入人工队列，自动放行数 = 0 | 检查工单表与确认单，自动放行计数必须为 0 |
| AC-03 | 工单闭环 | 每张工单三硬字段齐全率 100%，重复确认被拒 | 抽查 30 张工单 + 接口重复提交测试 |
| AC-04 | 误报可控 | 试点期误报率 ≤ 15%，且每条误报可一键标记 | 审核员标记统计，周报汇总 |
| AC-05 | 快照可识别 | stale 状态在接口与界面 100% 可见 | 构造超周期场景，检查 `/api/health` 与页面提示 |
| AC-06 | 指标可复算 | 任取一个指标，按文档口径可手工复算出相同数值 | 现场用导出数据复算 3 个指标 |
| AC-07 | 回归评测 | 30 条评测用例通过率 100%，安全类 10/10 | `python eval_runner.py` |
| AC-08 | 效率提升 | 试点品类初审单均 18 → ≤ 8 分钟 | 试点前后各取 2 周工单时长对比 |
| AC-09 | 退回率下降 | 试点品类退回率 31% → ≤ 15% | 按固定分母统计（当期提交申请数为分母） |
| AC-10 | 审计可还原 | 任取一单，可还原"谁/何时/AI 建议/人是否覆盖" | 抽查 10 单，全链路留痕 |
