## 二、首次部署步骤

1. 拉取源码：`git clone https://github.com/Wuminnn/NewStock.git`（或下载压缩包解压）。
2. 安装依赖：`pip install -r requirements.txt`（Python ≥ 3.10）。
3. 配置环境变量（可选）：
   - `PORT`：监听端口，缺省 8000；设置后自动绑定 `0.0.0.0`；
   - `SECRET_KEY`：JWT 签名密钥，生产必须 ≥32 字符；
   - `ENV=prod`：启用生产安全自检（默认密钥会拒绝启动）。
4. 启动：`python run.py`。首次启动自动完成：建表（16 张）、创建三个角色账号、导入《审核制度.md》示例知识库并构建检索索引。
5. 验证：浏览器打开登录页，用 admin 登录，进入「管理后台 → 系统健康」确认快照状态 `stale=false`。

## 五、日常运行

- **每日开机**：确认进程存活后访问 `/api/health`，若 `knowledge_snapshot.stale=true`，说明制度文件晚于索引构建，进入管理后台上传或重建索引。
- **人工处置队列**：Agent 遇到冲突或低置信度会转人工（工单含 task_no/reason/handler），管理员当日确认闭环，备注处置结论。
- **审计抽查**：每日抽 3 条会话核对「回答是否挂靠制度条文」，发现未挂靠的用 flag 标记。
- **指标巡检**：每周看一次 `/api/admin/metrics`，重点盯冲突拦截率（目标 ≥97%）与误报申诉率。

## 六、备份与恢复

- **数据备份**：`python scripts/backup.py`（SQLite 主库 + WAL 快照打包到 `backups/`，保留最近 N 份）。
- **定时备份**：`python scripts/install_schedule.py` 注册每日计划任务（Windows 计划任务 / crontab 等价）。
- **恢复步骤**：停进程 → 用备份包覆盖 `data/` 下的库文件 → 重启 → 访问 `/api/health` 校验 → 抽查一条历史会话可打开。
- **保留策略**：`scripts/retention.py` 清理过期备份与超期审计数据，建议保留 30 天。

## 七、故障处置速查

| 现象 | 排查 | 处置 |
|---|---|---|
| 登录 401/403 | 账号是否被停用、JWT 是否过期 | 重新登录；admin 重置密码 |
| 问答报「未找到依据」 | 知识快照是否 stale | 重建索引（管理后台上传制度） |
| SSE 无响应 | `/api/health` 的 sse.active 是否触顶 | 等待释放；必要时重启进程（幂等工单会恢复） |
| 接口 429 | 触发限流/配额 | 查看 security-events 确认来源，属正常防护 |
| Agent 卡在确认 | 确认单待签核 | `/admin/agent` 里由授权人签核或中断 |
| 数据库锁定 | WAL 文件异常 | 备份后重启；避免多进程同时写 |

## 九、已知边界（如实说明）

- MVP 为离线演示口径：问答依据全部来自本地知识库检索，不调用外部大模型；`llm_today` 指标在接入真实 LLM 后生效。
- 合成训练数据不代表真实客户验收；收益数字均为待验证假设。
- 单机 SQLite 部署适用于试点（≤50 并发）；规模化需迁移 PostgreSQL 并加只读副本，见《07_详细项目设计方案》部署章节。
